# Decisions

Deviations, clarifications and library notes made while implementing `PLAN.md`.
Every entry records what the plan said, what was done, and why.

| ID | Task | Decision |
| --- | --- | --- |
| D1 | T0.1 | `typescript` is pinned to `~5.9.3` instead of the current `7.0.2`: `typescript-eslint@8.73` (used by ESLint 10) declares `typescript >=4.8.4 <6.1.0`. TypeScript 7 will be adopted when the lint toolchain supports it. Vite 8, React 19.3, Tailwind 4.3 and ESLint 10 are current versions as verified against npm on 2026-11-22. |
| D2 | T0.1 / T3.2 | `zod` was added (as the plan explicitly permits in T5.3) and is shared by the Worker and the browser for a single API contract (`src/contracts.ts`). Zod 4 is used. |
| D3 | T3.2 | The plan's `responseMimeType: application/json` (generateContent-era field) has been superseded by the Gemini **Interactions API**. The Worker calls `POST /v1beta/interactions` with `response_format: { type: 'text', mime_type: 'application/json', schema }` and reads `output_text`, per current Google docs. Model is `gemini-3.8-flash` (current stable Flash); `gemini-2.5-flash` is deprecated and routes elsewhere from 2026-12-01. The exact model string lives in the shared, environment-free `src/shared/constants.ts` and is re-exported by `src/config.ts`. |
| D4 | T3.1 | Groq still uses `whisper-large-v3-turbo`, `response_format=verbose_json`, `timestamp_granularities[]=word`, as confirmed in current Groq docs. |
| D5 | T0.4 / T3.3 | Rate limiting uses a **Durable Object** (one instance per hashed IP) with a fixed 60-second window plus a rolling daily job counter. A small in-memory limiter is used only when the binding is absent (local `wrangler dev` before the binding is configured); this is not used in production. |
| D6 | T8.3 | ffmpeg.wasm is loaded with a single-threaded core, so no COOP/COEP headers are required; `public/_headers` is intentionally omitted. If threads are enabled later, add the headers. |
| D7 | T3.3 | Worker tests run in Vitest's node environment with mocked bindings/fetch rather than `@cloudflare/vitest-pool-workers`: all limit/CORS/error-path logic is pure and does not need miniflare. This keeps `npm test` fast and deterministic. |
| D8 | T2.1 | Audio is encoded to Opus inside an **Ogg** container (Groq accepts `ogg`) via Mediabunny's `AudioBufferSource` with `transform: { numberOfChannels: 1, sampleRate: 16000 }`. This streams chunks through `StreamTarget` and avoids hand-rolling a WebCodecs resampler. If Opus encoding is unsupported, AAC in MP4 (`m4a`) is used instead and recorded in `config`/UI. |
| D9 | T7.2 | Captions use the local system font stack (`system-ui`/`Arial`, no network request) instead of a downloaded webfont. Any locally bundled font can be substituted by changing `CAPTION_FONT` in `src/config.ts`. |
| D10 | T9.1 | MediaPipe Tasks Vision 1.2.3 is used. The WASM/model assets are loaded from URLs in `config.ts`; if they cannot be fetched, tracking falls back to a static centred crop with a visible notice. No user media is uploaded to load them. |
| D11 | T1.2 | `File` objects are read exclusively through Mediabunny's `BlobSource`, which performs bounded, lazy ranged reads. `file.arrayBuffer()` is never called on the source video. |
| D12 | T7.1 | Mediabunny's `CanvasSink` performs the keyframe seek + forward decode; frames are drawn into a separately sized output canvas and encoded with `CanvasSource`. Encoders are checked with `VideoEncoder.isConfigSupported` and walked across a profile list before starting the output. |
| D13 | T6.4 | The editor's caption overlay and the renderer call the same pure `drawCaptions` function, so preview and export use identical layout code. |
| D14 | T3.2 | The Gemini Interactions request sets `store: false` (no provider-side transcript retention; stateless calls do not need `previous_interaction_id`) and the documented `Api-Revision: 2026-05-20` header. Google's current docs still list `gemini-3.8-flash` as a supported Flash model alongside Gemini 4; it remains the selected cost-appropriate model. |
| D15 | T0.4 | The current Wrangler/workerd module runner requires a default export; a module with only a named `fetch` returned HTTP 500 for every request. `worker/src/index.ts` now exports both the named handlers used by Vitest and a default `{ fetch, RateLimiter }` object. |
| D16 | T8.2 | A bare `TypeError` from `fetch()` was shown to users as "Failed to fetch" with a generic action. `/transcribe` and `/highlights` now normalize it to `NetworkError` with a message pointing at the Worker/origin. `ALLOWED_ORIGIN` accepts comma-separated exact origins (localhost and 127.0.0.1 dev ports are allowed by default), and `npm run preview` proxies the API like `npm run dev`. |
| D17 | T3.1/T3.2 | Added `MOCK_PROVIDERS=true` in gitignored `worker/.dev.vars` so the full app can be exercised without API keys. Mock responses carry `X-Snapcut-Mock: true`; the deployed `worker/wrangler.toml` never enables it. |
| D18 | T7.3 | Large blob downloads failed in Chrome when the temporary anchor/object URL was released after 30 s. The anchor now lives 60 s and the URL 5 min, and an empty render is rejected with a clear message. |
| D19 | T9.1 | UI usability pass: Tailwind v4 treats `min-h-36` as `9rem` (144 px), so every button using it was oversized. Replaced with the `.btn` 44 px baseline, made the theme toggle a 44×44 icon button, removed hidden file inputs from the tab order and accessibility tree, added Step 1/2/3 labels, a plain-language export count, and a sticky mobile export bar so the primary action is always reachable. Clip rows now have a 44 px minimum tap target. |
| D20 | T9.1 | Second layout pass per user feedback: removed the left sidebar so the editor owns the main area, moved the primary Export control to the top-right of the file toolbar, and turned the clip list into a full-width horizontal strip. Source and 9:16 preview surfaces now share a responsive height (`--box-h`) and derive their widths from their own aspect ratios, so heights match with no letterboxing. Because `object-contain` can still letterbox unusual aspect ratios, `CropBox` receives the measured displayed-video rectangle in CSS pixels so the crop overlay stays accurate. |
| D21 | T6.2 | The trim handles were easy to miss and only reacted to precise handle drags. Trim controls were first given typed start/end inputs and track-level pointer capture; in the design rebuild they moved into `Timeline.tsx` as draggable `−`/`+` handles on the green clip, which keeps the interaction in the place users expect from a video editor. |
| D22 | T9.1 | The project's `design.md` is the authoritative UI spec. Rebuilt the interface as its dark, rounded video-editor: full-bleed window, top bar with project title / settings / blue pill Export, preview pane with floating tool rail, selected text overlay and playback scrubber, timeline with ruler/playhead/tracks, and a properties panel with sliders, position/rotation fields, cover drop zone, and effect settings. Inline SVG icons are used instead of adding `lucide-react` (no unlisted dependencies). Functional controls (crop, captions, trim, export, auto-follow) remain wired to the existing store; presentational controls (size/position/rotation/gizmo/effects) are local UI state only. Source video still stays local — only the export preview canvas reads decoded frames. |
| D23 | T9.1 | Per follow-up feedback the editor now occupies the entire browser window (`h-[100dvh] w-full`, no outer margin or rounded frame). `html`/`body`/`#root` are `overflow: hidden` so the page never scrolls; only the properties panel scrolls internally. The "restored cached transcript" notice is now a floating toast overlay instead of an in-flow panel, so it cannot shift the layout. |
| D24 | T9.2b | Follow-up feedback rejected presentational-only controls. The properties panel now groups only real edit controls (timing, captions, framing, clip details) with aligned label/value rows and a sticky action bar; the fake transform gizmo, size/rotation fields and cover-effects sliders were removed. The preview tool rail keeps the design's two named tools (`Text`, `Crop`) plus working centre/zoom/caption/transport actions; it scrolls internally and can be dragged by its grip so it never covers the playback bar. No new dependencies were added. |
| D25 | T6.2 / T9.2b | Timeline trim handles now use pointer capture on the live clip and convert pointer movement to seconds using the measured track width, so both handles and the clip body slide smoothly. Track labels include a ruler-height header and the optional expanded text-property rows are mirrored in the lane area, keeping `Sunset.jpg`/`Text`/`Roll.mp3` aligned with their tracks at every viewport; `e2e/layout.spec.ts` asserts identical row tops at 1280×900, 1366×768 and 942×620. |
| D26 | T7.3 / T9.2b | Clip export checkboxes are a multi-select convenience, not a gate: with none ticked, `renderSelected` exports the active clip (or every clip when none is active), and the Export button stays enabled whenever a clip exists. The project title input is hidden on the picker screen and borderless in the editor. The left column was widened (properties 280/320 px) and both preview and timeline now stretch to fill their column; the compact top bar is 61 px instead of 81 px. |
| D27 | T9.2a | The preview video intentionally keeps `object-fit: contain` instead of `design.md`'s `cover`: `CropBox` maps normalized crop coordinates onto the measured displayed-video rectangle, and `cover` would clip part of the source so the crop overlay would no longer match the export. The 9:16 inset canvas still shows the exact exported crop and captions. |
| D28 | T9.3 | Undo/redo is a bounded `Clip[][]` past/future stack in the Zustand store. Rapid changes to the same field/clip collapse into one step by refreshing a coalescing timestamp on every repeat edit, so a long pointer drag stays one step. Undo is `Ctrl/Cmd+Z`, redo is `Ctrl/Cmd+Shift+Z` or `Ctrl+Y`; shortcuts are ignored while typing in a field. Playback shortcuts live in `PreviewPane` (Space, arrows, J/K/L, F) so they use the real video element without a global second player. |
| D29 | T9.4 | Split, duplicate and delete are store actions so selection and history stay consistent. Split uses the shared preview playhead, clamps to at least 0.5 s on each side, splits word timing at the boundary and selects the right half. Duplicate offsets words with the clip if the source duration allows it; delete selects the neighbouring clip. Buttons live in the Timeline header; numbers and text remain keyboard-editable in Properties. |
| D30 | T9.5 | "Remove silences" uses word gaps longer than 0.75 s, keeps the largest seven gaps, and turns the remaining keep-ranges into separate clips so each can still be trimmed/exported. Gaps outside the clip range are ignored by filtering words to the clip first; if no removable gap exists, the user gets a clear notice instead of a silent no-op. |
| D31 | T9.6–T9.8 | New per-clip fields (`volume`, `muted`, `fadeInSec`, `fadeOutSec`, `speed`, `captionLayout`) are optional so projects saved before these controls still load. Defaults are applied through `clipOptions.ts` rather than mutating old clips. |
| D32 | T9.6–T9.7 | Audio effects are applied on the output timeline: source samples are re-timed by `sourceTime / speed`, then gain/fade is applied there. Mediabunny still resamples the mix to 48 kHz stereo; the ffmpeg.wasm fallback uses `volume`, `atempo`, `afade` and `setpts`. Speed `1` keeps the original `canvases()` render path; other speeds use frame timestamps. |
| D33 | T9.8 | Caption layout options are multipliers/positions around the existing style defaults (font size, vertical position, forced background, outline). This preserves the exact default rendering used by earlier tests while giving the Properties panel real controls. |
| D34 | T9.7–T9.8 | `clip.words` remain source-absolute. Preview and renderer pass the source video time to `drawCaptions`; only the output duration is scaled by clip speed. |
| D35 | T9.9 | The timeline filmstrip is decoded in a dedicated `filmstrip.worker.ts` with Mediabunny's `CanvasSink` at 96×54 and returned as small JPEG blobs. The source is still read through `BlobSource` (bounded ranged reads) and never uploaded. Frames span the whole source, so trimming/splitting does not invalidate them; object URLs are revoked when a new file replaces the strip. |
| D36 | T9.9 | Every preview seek is quantized to a 30 fps frame boundary. The filmstrip is the top row of the single timeline track, has fixed-width thumbnails in a horizontal swipe/scroll container (native `pan-x`, wheel-to-horizontal), clicking a thumbnail seeks to that frame, `Cut at frame` (or `X`) splits at the exact frame under the playhead, and the playback bar shows the current frame number. |
| D37 | T9.2b/T9.9 | The timeline ruler is pointer-draggable with word-boundary snapping for trims, the header exposes zoom/select-all/clear, and clip chips show speed/mute/fade badges. The preview has audio audition, an expandable 9:16 export inset, unique wider scrub ticks, frame-step buttons and fullscreen; duplicate transport controls were removed from the tool rail. |
| D38 | T9.9 | The timeline is a single usable track: ruler, swipeable frame strip, one clip bar with export checkbox and the required `Drag clip start`/`Drag clip end` handles. Track-label columns, duplicate source/caption lanes, zoom and select-all/clear controls were removed; undo/redo stay in the top bar and split/duplicate/delete/remove-silences stay in the timeline header. |
